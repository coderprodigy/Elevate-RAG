## How to read them

* **These are not the plan's research results.** E1–E6 and A1–A4 have not been run: they need
  GPU time or an API budget, and the LLM judge must first pass the human agreement gate
  (κ ≥ 0.6 against two annotators). G1 runs exist to prove the pipeline and to find problems
  cheaply before that spend; the defects each one surfaced are listed in its write-up.
* Every accuracy comes with a 95 % bootstrap CI; paired differences use exact McNemar with Holm
  correction. With n = 20 one question is 5 points, so only very large differences can be
  significant.
* Judge-based accuracies from small local judges are unreliable (see `g1/G1_RESULTS.md`,
  finding 1); each G1 write-up also reports a judge-free check (gold answer contained in the
  response).
* Latency is reported only over queries whose LLM calls actually ran (not served from cache);
  `n/a` means a variant reused cached calls from an earlier variant.
