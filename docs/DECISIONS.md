# Decisions

- Use Python 3.12 on the assigned Darwin arm64 development machine. The host provides Python 3.12.13 and uv 0.11.8. Available memory is 16 GB. Docker Desktop was available for the service verification pass.
- Pin LightRAG 1.5.8 from the installed package cache. Use its custom chunk ingestion and structured retrieval interfaces. The custom chunk entry point is deprecated upstream and the pin and provenance tests guard the compatibility dependency. [LightRAG](https://github.com/HKUDS/LightRAG), [package](https://pypi.org/project/lightrag-hku/).
- Use passage-only generator inputs across modes. Graph profiles influence the selection of passages and graph retrieval traces retain entity and relation metadata. This applies the same source citation and context policy throughout.
- Treat the proposal’s estimated run counts as planning figures. Enumerate blocks from the named factors and dataset scopes. Preserve both GraphRAG-Bench domains as separately measured strata.
- A synthetic fixture confirms plumbing and accounting. Benchmark outcomes require upstream dataset versions and frozen provider settings. The reference model tier and the separate judge family require runtime verification before study execution.
- Use an upstream-specific loader for each benchmark. RAGRouter-Bench has a separate validation boundary for its five-fold evaluation. Resolve NQ distractors from its Wikipedia candidates and keep annotated gold passage IDs outside retrieval. [Natural Questions](https://github.com/google-research-datasets/natural-questions), [HotpotQA](https://hotpotqa.github.io/), [MuSiQue](https://github.com/StonyBrookNLP/musique), [MultiHop-RAG](https://github.com/yixuantt/MultiHop-RAG), [GraphRAG-Bench](https://github.com/GraphRAG-Bench/GraphRAG-Benchmark), [RAGRouter-Bench](https://github.com/ziqiwang0908/RAGRouter-Bench).

- Use tie-aware exact-FAISS matching at the top-10 cutoff. Equivalent exact scores receive equal credit, preventing arbitrary tie order from penalizing a backend.
- Pin RAGAS 0.4.4 after 0.4.3 failed to import with the available LangChain community integration. Verify the adapter through the SDK with a local mocked response. [RAGAS compatibility change](https://github.com/vibrantlabsai/ragas/blob/v0.4.4/src/ragas/llms/base.py)
- Preserve the graph ingestion path for the optional LlamaIndex schema fallback. Adapt separately validated structured triples into LightRAG’s pinned extraction response format so entity, edge and passage provenance remain on the same ingestion contract. [LlamaIndex property graph documentation](https://developers.llamaindex.ai/python/framework/module_guides/indexing/lpg_index_guide/)
- Pin the Qdrant client to the server’s 1.16 series. Add the PostgreSQL 16 Apache AGE package to the pgvector image to support both storage roles and record the effective server version in any E4 run. [Qdrant client](https://pypi.org/project/qdrant-client/1.16.2/), [PostgreSQL project package](https://apt.postgresql.org/pub/repos/apt/pool/main/p/postgresql-16-age/)
